# Accessibility review

## Target

WCAG 2.2 Level AA. Q3 of `docs/m3-phases.md` Phase 5 fixed this level rather than A or AAA:
AA is the level most funders and journals require of a shipped tool, and the app's own inputs and
tables are simple enough to reach it without redesigning the DataGrid or the navbar, both of which
are third-party components this project does not author.

## Method

`tests/e2e/test_a11y.py` runs axe-core through the `axe-playwright-python` bridge, version 0.1.8,
bundling axe-core 4.12.1, against Chromium 151.0.7922.34 (the revision Playwright 1.62.0 pins).
Each run scopes axe to the rule tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` and `wcag22aa`, so a
rule outside those tag sets (axe's own best-practice rules, for instance) is not asserted on.

Nine page states are checked:

- the Load screen before any file is chosen (`test_load_screen_before_data`);
- each of the seven screens (Load, Validate/QC, Navigate, Rank, Compare, Selection list, Export)
  after the fixture is loaded and two Rank rows are selected, so Compare and the Selection list
  have content (`test_every_screen_after_load`);
- the Compare screen with the fixture loaded but nothing yet selected, its own empty state
  (`test_compare_empty_before_selection`).

`test_status_is_never_colour_alone` checks that colour is never the only carrier of a status: every
`target_*_status` and `avoid_*_status` cell in the Rank grid has non-empty text (not just a
background tint), every Compare `.status-chip` badge has non-empty text, and every Compare
`svg[role=img]` chromosome strip carries a non-empty `aria-label`.

`tests/e2e/test_focus_order.py` walks focus with repeated `Tab` presses (up to 60) from `body`
after the fixture loads, reading `document.activeElement` on each stop. It asserts that no focused
element other than `body` has `offsetParent === null` (Chromium's cheap hidden-element test), that
an element with `role="tab"` is reached (the navbar's tab list), and that `#load-run` is reached
(the Load screen's own button).

## Fixes made in this app's own markup

- **`html-has-lang`.** `ui.page_navbar` was missing `lang`; `src/progeny_selector/app/app.py` now
  passes `lang="en"`.
- **Text-on-colour contrast for the "A" (recurrent-parent) state.** Black text on the Okabe-Ito
  blue used for parent-of-origin state A (`#0072B2`) measures 4.05:1, below AA's 4.5:1 for normal
  text; black passes (5.4:1 or better) on every other state colour and on all three status colours
  (pass, fail, unknown). `constants.py` adds `STATE_TEXT_COLORS`, a text-colour lookup keyed by
  state label and by status value, white only for `"A"`; `app/present.py::status_cell_styles`,
  `app/present.py::chip_style` and the Compare legend swatches
  (`app/screens/compare.py::_legend`) read the paired text colour from it instead of writing
  `#000000` as a literal. No background colour changed; the Okabe-Ito palette in `constants.py` is
  untouched.

## Known exceptions

Violations inside markup this app does not author are excepted in
`tests/e2e/test_a11y.py::KNOWN_A11Y_EXCEPTIONS` rather than patched, since there is no app-level
attribute or template to fix them from. Dated in `docs/adr/0023-accessibility-baseline.md`.

| rule id | where | reason | ADR line |
| --- | --- | --- | --- |
| `aria-allowed-attr` | Validate, Rank and Selection-list `render.DataGrid` tables | `aria-rowcount`/`aria-multiselectable` on the grid's own `<table>` come from Shiny's DataGrid component, not this app's markup | 2026-09-25 |
| `label` | Validate and Rank grid per-column filter inputs (`filters=True`) | the filter `<input>`s are generated by `render.DataGrid`; this app passes `filters=True` and does not template the inputs themselves | 2026-09-25 |
| `scrollable-region-focusable` | `bslib` card-body containers under `page_navbar(fillable=True)` on Validate, Compare and the Selection list | the scroll container and its missing `tabindex` are bslib's fillable-layout CSS, applied to every `ui.card()` in the app, not an attribute this app's screens set | 2026-09-25 |

## Keyboard

See `docs/keyboard-walkthrough.md` for the full screen-by-screen tab order. The Rank grid needs a
mouse: Shiny's DataGrid does not give its cells keyboard focus in the `Tab` sequence, a limit of
that third-party component recorded there and in `docs/adr/0023-accessibility-baseline.md`, not
something this review adds a workaround for.

## Not verified

- **Screen readers.** No assistive technology (NVDA, JAWS, VoiceOver) is available in this
  environment; ARIA roles and labels are checked structurally by axe, not read aloud by a screen
  reader.
- **Firefox and Safari.** The e2e suite drives Chromium only, the browser Playwright's Python
  package pins.
- **Reflow at 320 px (WCAG 1.4.10).** Not checked: the DataGrid's own scroll containers would fail
  a 320 px reflow test as data tables legitimately do, so a failure there would not distinguish an
  app defect from the component's own designed behaviour at that width.
- **Lighthouse.** Lighthouse needs a Node.js toolchain this repository does not have; axe-core
  covers the same WCAG success criteria this review targets.
