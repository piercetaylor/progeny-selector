## Inherited work, all recorded in the repo

- **The obvious first fix.** `io/export.py` does not validate `next_generation`; an empty or
  whitespace label writes ids like `BC2F1-F1-001--001` and a blank `generation` column, on both the
  CLI and the Export screen. It is the same two-callers-one-rule shape as the placeholder-row count
  closed in `6b1d3a4`, so that commit is the worked example. Recorded in the PLAN.md handoff and in
  the `docs/m2-phases.md` checklist note.
- **Question B is still open and still Pierce's.** No linked consecutive-generation public dataset
  was found, so the two-generation *real-data* round trip has never run. The synthetic round trip
  shipped (phase 8, `tests/test_round_trip.py`). The M2 verification block records this as not run,
  with the reason.
- **The `possible_duplicate` semantics question**, raised by the phase 8 reviewer and probably M3
  work. The measure saturates: sib IBS over informative markers has mean about 1 − 0.25·(parent
  het), so segment-identical sibs of a nearly homozygous parent sit above any threshold below 1.0,
  while a true duplicate with ordinary call error sits below 1.0. No threshold separates them. What
  would discriminate for a breeder is whether a pair shares `family_id` — a same-family
  late-generation pair is expected, a cross-family or cross-generation pair at 0.995 is the alarming
  one — and whether discordance is exactly zero. `docs/adr/0017`'s BC3F1 section has the numbers.
- **Two things never exercised.** `soysnp_positions.py --download` verifies each directory's
  `CHECKSUM.*.md5`, but only the `.gff3.gz` files have ever been fetched, so that path has not run
  against a live checksum file. And decision 9's KASP long-format headers (`SubjectID`, `SNPID`,
  `Call`) are still unconfirmed against a primary source — no real LGC export has been seen.
  `docs/adr/0019`'s addendum says so.

## How the work was run, and why

This is the part worth carrying over; the rest is in the diff.

- **Dispatch one phase at a time**, to an `implementer` agent. Opus for core, io, model, contract
  and `docs/data-formats.md`; sonnet for UI, scripts, CI and docs. Run a `reviewer` agent on every
  diff touching core, io, model or contract. Doers never run git — the main session commits. Two
  phases can run in parallel only on disjoint files, and `CHANGELOG.md` is the collision point every
  time: tell both agents not to touch it and insert their reported lines yourself.
- **Demand a discriminating input for every new test, and make the doer prove it** by neutralising
  the production line the test covers, confirming the failure, and reporting which line. Five
  assertions in M2 would have passed with the behaviour they covered removed, and no gate caught any
  of them; they are enumerated in the PLAN.md handoff. This check found all of them. One of the five
  was created by an over-specified instruction from the main session, so it applies to your own
  briefs too.
- **When an agent says a test pins third-party or environment-dependent behaviour and it cannot
  neutralise it, believe it.** The one M2 test flagged that way is the one that later went red in
  CI on a runner difference. The right resolution there was to delete the assertion, not to wrap it
  in a wait — polling fixes a race toward one eventual state, not two different final states.
- **Push before calling a phase finished.** `e2e`, `export` and `r-reader` are CI-only and are not
  local gates. Read the run against the right commit: `gh run list` will hand you a run for the
  previous HEAD if the new one has not been created yet.
- **Decisions belong to Pierce.** When a finding needs a semantics choice rather than a fix — the
  duplicate overlap floor, the beyond-length weighting — put it to him with a recommendation and
  the tradeoff, and let the fix round proceed on everything else meanwhile. He answers quickly and
  has taken the recommendation each time, but the alternatives were real.
- **Gates**, from `CLAUDE.md`, run with the project venv `.venv/Scripts/python.exe` (the bare
  `python` on PATH is an unrelated MGLTools install): `ruff check .`, `ruff format --check .`,
  `mypy`, `pytest`, `scripts/check_contract.py`, plus regenerating the fixture and confirming
  `git diff --exit-code -- tests/fixtures` is clean. Baseline at HEAD: **405 passed, 27 deselected**;
  `pytest -m e2e` 26 passed, 1 skipped.
- The contract mirror command is `python3 scripts/check_contract.py ../isoline-browser`. The sibling
  repo is `piercetaylor/backcross` but the folder on disk is still `isoline-browser`; both names are
  now in `CLAUDE.md`. Any contract change starts in backcross and is copied here.
